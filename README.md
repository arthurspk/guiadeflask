## :dart: O guia para alavancar a sua carreira

> Flask é o micro-framework web mais popular do Python: minimalista por design, sem ORM ou sistema de formulários embutidos, ele te dá só o essencial (roteamento, templates Jinja2, sessões) e deixa você escolher o resto. É a porta de entrada de quem já sabe Python e quer construir uma API ou aplicação web sem a curva de aprendizado de um framework "baterias inclusas", e a base de produtos como Pinterest, Netflix (ferramentas internas) e LinkedIn. Este guia reúne roadmap, tutorial oficial, documentação, livros, canais, extensões do ecossistema (Flask-SQLAlchemy, Flask-Login, Flask-RESTX, Celery) e um capítulo sobre usar IA na prática com Flask — tudo verificado, com prioridade para conteúdo gratuito e em português.

## 🗺️ Roadmap
- [roadmap.sh — Backend Roadmap](https://roadmap.sh/backend) — Roteiro geral de back-end da comunidade; Flask aparece como um dos frameworks leves recomendados para quem já sabe Python.
- [roadmap.sh — Python Roadmap](https://roadmap.sh/python) — Trilha de fundamentos de Python que antecede o estudo de qualquer framework web, incluindo Flask.
- [Design Decisions in Flask (documentação oficial)](https://flask.palletsprojects.com/en/stable/design/) — Os princípios por trás das decisões de design do framework, incluindo o que "micro" realmente significa em "microframework".
- [Flask Changelog (documentação oficial)](https://flask.palletsprojects.com/en/stable/changes/) — Histórico completo de versões, da 0.1 à 3.1.3 (atual), útil para acompanhar o ritmo de evolução do framework.

**Trilha resumida** (siga na ordem; cada etapa tem recursos nas seções abaixo):

1. **Fundamentos de Python** — variáveis, funções, orientação a objetos, `venv`/`pip`. Flask pressupõe Python intermediário.
2. **Primeira aplicação** — `flask --app nome run`, roteamento (`@app.route`), a aplicação mínima de uma única página.
3. **Templates e arquivos estáticos** — Jinja2, herança de templates, CSS/JS/imagens servidos pelo Flask.
4. **Requisição, formulários e sessão** — objeto `request`, métodos GET/POST, `session`, mensagens flash.
5. **Banco de dados** — Flask-SQLAlchemy, migrations com Flask-Migrate, ou SQLite puro para projetos simples.
6. **Autenticação** — Flask-Login para sessões de usuário, Flask-WTF para formulários com proteção CSRF.
7. **Organização do projeto** — Blueprints, application factory (`create_app`), estrutura em pacote para projetos maiores.
8. **APIs REST** — Flask-RESTX ou APIFlask para expor endpoints JSON documentados (OpenAPI/Swagger).
9. **Testes e produção** — testes com o test client do Flask/pytest, Gunicorn, variáveis de ambiente, deploy.
10. **Especialização** — tarefas assíncronas (Celery), WebSockets (Flask-SocketIO), cache, rate limiting, observabilidade (Sentry).

## 🚀 Por onde começar
1. **Instale o Python** e crie um ambiente virtual; depois instale o Flask com `pip install flask` (veja o [guia oficial de instalação](https://flask.palletsprojects.com/en/stable/installation/)).
2. **Siga o Quickstart oficial** — [Quickstart (documentação oficial)](https://flask.palletsprojects.com/en/stable/quickstart/): a aplicação mínima de Flask em poucas linhas e os conceitos essenciais (rotas, templates, request, sessão).
3. **Faça o tutorial oficial completo** — [Tutorial: cria o app Flaskr (documentação oficial)](https://flask.palletsprojects.com/en/stable/tutorial/): constrói um blog do zero, com banco de dados, autenticação e testes — o ponto de partida recomendado pela própria documentação.
4. **Assista a um vídeo introdutório em português** — [O que é Flask - Micro framework de Desenvolvimento Web no Python (Hashtag Programação)](https://www.youtube.com/watch?v=f5U1bHTPe5w) ou [Aprenda Flask em 10min (Hashtag Programação)](https://www.youtube.com/watch?v=WnaRrfqq5uw).
5. **Leia o Mega-Tutorial de Miguel Grinberg** em paralelo — [The Flask Mega-Tutorial, Part I: Hello, World! (blog.miguelgrinberg.com)](https://blog.miguelgrinberg.com/post/the-flask-mega-tutorial-part-i-hello-world) — referência mundial para quem já tem alguma base e quer um projeto completo, com banco de dados, e-mail, API e deploy.
6. **Aprenda a organizar o projeto** com [Modular Applications with Blueprints (documentação oficial)](https://flask.palletsprojects.com/en/stable/blueprints/) assim que o projeto passar de um único arquivo.
7. **Depois do básico, aprenda a expor APIs** com [Flask-RESTX](https://flask-restx.readthedocs.io/en/latest/) ou [APIFlask](https://apiflask.com/).
8. **Publique um projeto no GitHub** e faça o deploy — veja [Deploying to Production (documentação oficial)](https://flask.palletsprojects.com/en/stable/deploying/); planos gratuitos como Render, Railway, Fly.io ou PythonAnywhere funcionam bem para começar.

Seu primeiro projeto em poucos comandos:

```bash
python3 -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate
pip install flask
echo 'from flask import Flask

app = Flask(__name__)

@app.route("/")
def hello():
    return "Hello, World!"' > app.py
flask --app app run --debug
```

## 🤖 IA na prática
Flask é minimalista e não impõe estrutura — isso é ótimo para liberdade, mas significa que a IA frequentemente "inventa" convenções que não existem no framework (tentando aplicar padrões do Django, por exemplo). Ela é excelente para gerar rotas, templates e boilerplate de extensões, mas erra bastante quando o projeto cresce e depende de como *você* organizou a aplicação.

**Para aprender**
- Peça para a IA explicar a diferença entre o contexto de aplicação (`app context`) e o contexto de requisição (`request context`) do Flask com um exemplo — é um dos pontos que mais confunde iniciantes e a documentação oficial dedica duas páginas inteiras ao assunto.
- Peça exercícios com o test client do Flask (`app.test_client()`) sobre o tópico que está estudando: você escreve a rota, o teste diz se o comportamento está correto.
- Peça para a IA comparar como o mesmo recurso (autenticação, upload de arquivo, paginação) seria implementado "na unha" versus usando uma extensão (Flask-Login, Flask-WTF) — ajuda a entender o que a extensão resolve de fato.
- Use a IA para revisar sua estrutura de Blueprints e sugerir como dividir uma aplicação que cresceu demais em um único arquivo.

**Para trabalhar**
- Use GitHub Copilot, Cursor ou Claude Code para gerar rotas, schemas de validação (Marshmallow/Pydantic) e testes a partir dos seus modelos, e para explicar tracebacks do Werkzeug.
- Depois de aceitar uma sugestão que mexe em autenticação ou sessão, releia com atenção — é a área onde a IA mais introduz falhas de segurança sutis em projetos Flask (ver abaixo).
- Peça para a IA revisar suas queries do SQLAlchemy em busca do problema de N+1 queries, comum quando um endpoint é gerado rápido demais sem `joinedload`/`selectinload`.
- [GitHub Copilot](https://github.com/features/copilot) — Autocomplete e chat com IA no editor; gratuito para estudantes e com plano free.
- [Cursor](https://cursor.com/) — Editor baseado no VS Code com IA integrada ao fluxo de trabalho.
- [Claude Code](https://code.claude.com/docs/en/overview) — Agente de código no terminal: escreve testes, revisa rotas e explica erros do Flask/Werkzeug.

**Limites e boas práticas**
- IA **inventa nomes de parâmetros e métodos de extensões** que não existem na versão instalada (ex.: assinaturas antigas do Flask-Login ou do Flask-WTF) — confira sempre a documentação da versão em uso.
- Como o Flask não tem proteção CSRF nem escaping de template ativados por padrão em todo lugar (dependem de você usar Flask-WTF e Jinja2 corretamente), desconfie de formulários gerados por IA sem `{{ form.csrf_token }}` ou sem `render_template` (evite montar HTML com f-strings).
- Nunca aceite sugestões que exponham a `SECRET_KEY`, credenciais de banco ou rodem com `debug=True` em produção — o debugger interativo do Flask permite execução remota de código se exposto publicamente.
- Revise queries que a IA monta com SQL cru e f-strings/`.format()` em vez de usar o ORM ou parâmetros do `cursor.execute()` — é o padrão de SQL injection mais repetido por IA.
